# 角色素材放这里

每个角色一个文件夹，文件夹名 = `data/characters.js` 里的角色 `id`。
文件夹已经建好了，**直接把文件丢进去就行**，不需要改任何代码。

```
assets/characters/
├── moyu/                    摸鱼打工人
│   ├── idle.png             待机单张图（或者用 idle_01.png… 序列帧）
│   ├── attack.png           出手瞬间（可选）
│   ├── hurt.png             受击瞬间（可选）
│   ├── dead.png             阵亡（可选）
│   ├── icon.png             头像（可选）
│   ├── skill.png            技能特效贴图（可选）
│   ├── sfx/                 ← 音效放这里
│   │   ├── attack.wav
│   │   ├── skill.wav
│   │   ├── hurt.wav
│   │   └── death.wav
│   └── frames/              ← 你放原始素材/序列帧的地方，不会被自动加载
├── kunkun/
│   ├── idle_01.png          序列帧动画：按数字顺序播放
│   ├── idle_02.png
│   ├── attack_01.png
│   └── ...
└── ...
```

> **⚠️ 最容易踩的坑：图片必须放在角色文件夹的「根目录」下。**
> 扫描器**不会**递归进子文件夹。`frames/` 是专门留给"原始素材"的，
> 放在那里的图**不会被识别**（游戏里完全看不到）。
> 换图/加图之后记得跑一次 `node tools/scan-assets.js`，
> 它会打印每个角色识别到了什么 —— 没列出来的就是没生效。
>
> 常见症状：放好了图却还是几何图形 / 没有贴图，八成是目录层级放错了。

## 一、图片槽位

| 槽位 | 什么时候显示 | 缺省行为 |
|---|---|---|
| `idle` | 默认状态 | **最重要**，没有它就用几何图形 |
| `attack` | 每次出手的瞬间 | 缺失时回退到 `idle` |
| `hurt` | 被打中的瞬间 | 缺失时回退到 `idle` |
| `dead` | 阵亡后 | 缺失时画墓碑 |
| `icon` | 选择器 / 兜底 | 缺失时用 emoji |
| `skill` | 技能特效（可选） | 缺失时用代码特效 |

- **单张静态图**：`idle.png` → `.png` `.webp` `.jpg` `.svg`
- **序列帧动画（推荐）**：`idle_01.png`、`idle_02.png` … 扫描器会自动识别成一组动画
- **GIF 动图**：`idle.gif` → 浏览器原生播放，最省事
- **透明背景**推荐 PNG/WEBP，人物建议**居中、四周留一点空白**（游戏会按角色半径缩放，不会裁切）

### 图片格式：只有带透明通道的才不留白底

| 格式 | 能透明？ | 建议 |
|---|---|---|
| **PNG** | ✅ | **首选**。无损、带 alpha |
| **WEBP** | ✅ | 推荐。同质量体积更小 |
| JPG / JPEG | ❌ **不支持透明** | 只适合做整张背景图；当角色会拖一个白/黑方块 |
| GIF | ✅（1 位透明） | 可以，但只有"全透明/全不透明"，没有半透明边缘 |
| SVG | ✅ | 矢量，放大不糊，适合简单图形 |

> **重点**：JPG 没有 alpha 通道。把抠好的图存成 JPG，透明区域会变成白底，
> 游戏里角色就成了一个白色方块 —— 实测透明版那一圈是背景色 `rgb(14,23,50)`，
> 白底版就是纯 `rgb(255,255,255)`。**角色图一律存 PNG 或 WEBP。**

### 怎么把背景抠成透明

1. **在线一键抠图**（最省事，适合照片/复杂边缘）
   搜「remove.bg」这类工具，上传 → 下载，它直接给带透明的 PNG。
2. **图形软件手动抠**（适合自己画的图）
   Photoshop / GIMP / Krita / 画世界：
   用「魔棒」或「按颜色选择」点掉背景 → 删除 → 导出时**勾选透明度**，
   存成 **PNG**。
3. **本身就是透明底**（最理想）
   如果你用 AI 画图，直接用「透明背景 / transparent background」当提示词生成，
   或导出时选 PNG 带 alpha。
4. **命令行批处理**（图多的时候）
   `ImageMagick`：`magick in.jpg -fuzz 12% -transparent white out.png`
   Python：`Pillow` 读进来 → 把接近背景色的像素 alpha 设 0 → 存 PNG。

**自检一下再放进项目**：把导出的图拖进浏览器新标签页，如果**能看到背后的棋盘格**，
就是真透明；如果显示白底或黑底，说明透明丢了，重新导出。

#### 懒人做法：用自带脚本一键抠

不想开图形软件的话，项目里带了一个脚本（支持动图，会逐帧处理并保留动画）：

```bash
# 先看看效果（不写文件）
python tools/remove-bg.py assets/characters/ikun/idle.webp --dry-run

# 真正处理：背景越干净容差可以越小；--scale 顺便压一下尺寸
python tools/remove-bg.py assets/characters/ikun/idle.webp --tolerance 14 --feather 2 --scale 384
```

它是从**四周边框**做洪水填充，只把「和边缘相连、颜色接近背景」的部分变透明 ——
所以角色身上的白色（白衣服、白球鞋）**不会被误伤**。

> 它还能处理**棋盘格底纹**：有些图导出时把"透明"预览的灰白格子烤进了像素里
> （单一颜色匹配只能干掉一半，会残留一片灰）。脚本会沿边框聚类出多种背景色一起处理。
>
> 参数怎么调：`--tolerance` 小一点更保险（默认 26，棋盘格建议 12~14）；
> `--feather 2` 能把边缘的浅色描边收掉；`--min-blob` 清掉细小噪点。
> 拿不准就先 `--dry-run` 看透明度百分比，再实际输出、合成到深色底上看一眼。

### 动图（GIF / 动画 WEBP）

**动画 WEBP 和 GIF 一样支持**，而且是同样的机制 —— 当作单张图加载，
由浏览器原生播放。扫描器认 `.webp`，所以 `idle.webp`、`skill.webp` 直接就能用，
不需要拆成序列帧。

> 注意：正因为是浏览器自己播的，**无头浏览器里测不到它在动**
> （`--headless` 不驱动动图，连 GIF 也一样）。这是测试环境的限制，不是文件坏了。
> 想要"能被自动化测试验证"的动画，用**序列帧**（`idle_01.png`…）。

### 为什么推荐序列帧而不是 GIF

| | 序列帧 | GIF |
|---|---|---|
| 播放节奏 | 由游戏循环控制，精确同步 | 浏览器自己计时，不受控 |
| 能否自动化测试 | ✅ 可以 | ❌ 无头浏览器不驱动 GIF |
| 能否暂停 / 变速 | ✅ 跟着游戏走 | ❌ 自己播自己的 |
| 制作成本 | 需要导出成单帧 | 一个文件搞定 |

所以：**做正式素材用序列帧，想快速看效果用 GIF**。两者可以混用，
甚至同一个角色 `idle` 用序列帧、`attack` 用单张图。

序列帧的命名只要以槽位名开头、按数字排序即可，扫描器按**数字大小**排序：
`idle_01.png`、`idle_02.png` … `idle_10.png`（推荐两位补零），也认 `idle-1.png`。
序列帧默认按 **8 帧/秒**播放。

### 我该选哪种？静态图完全够用

**没有任何格式是必须的。** 三种都能当 `idle`，选最省事的那个：

| 你手上有 | 怎么放 | 效果 |
|---|---|---|
| 一张透明 PNG | `idle.png` | ✅ **最简单，推荐先这样跑通**。角色静止但完全正常 |
| 一张 GIF | `idle.gif` | ✅ 会动，浏览器自己播 |
| 一组帧图 | `idle_01.png` … | ✅ 会动，节奏由游戏控制（**最推荐做正式素材**） |
| 什么都没有 | 不放图 | ✅ 自动用几何图形 + emoji 兜底，**游戏照样能玩** |

也就是说：**先用一张静态透明 PNG 把角色跑起来**，动画以后随时再加。
静态图不需要做任何额外配置，扫描器认 `idle.png` 就直接用。

> 一个常见误区：以为"没有 GIF 就不算动图、不能当待机"。
> 实际上待机只要有一张图就行，**静止的角色也是完全合法的待机**。

## 二、音效

放在角色目录下的 `sfx/`（也认 `audio/`、`sound/`、`sounds/`）：
`attack.wav` `skill.wav` `hurt.wav` `death.wav`，支持 `.wav .mp3 .ogg .m4a`。
**没有音效时会自动用内置合成音兜底**，所以只放一部分也完全没问题。

音效是**可选**的：一个都不放，游戏会用内置合成音，
听起来也不突兀（每个动作都有对应的默认音）。

## 三、命名别名（少改名）

扫描器认这些别名，忽略大小写，也支持 `idle_01.png`、`idle-2.gif` 这类前缀写法：

| 槽位 | 认得的名字 |
|---|---|
| idle | `idle` `stand` `default` `normal` `待机` `默认` |
| attack | `attack` `atk` `hit` `strike` `攻击` |
| hurt | `hurt` `damage` `pain` `受击` `受伤` |
| dead | `dead` `death` `die` `grave` `阵亡` `死亡` |
| icon | `icon` `avatar` `head` `头像` |
| skill | `skill` `ult` `special` `cast` `技能` `特效` |

> 如果同一槽位放了一个**完全同名**的文件（如 `idle.png`）和若干序列帧（`idle_01.png`…），
> 优先用完全同名的那张。想用序列帧就别放 `idle.png`。

## 四、让游戏读到新素材

丢完文件后，在 `meme-arena` 目录执行一次：

```bash
node tools/scan-assets.js
```

它会重新生成 `assets/manifest.js`（游戏读取的清单），并打印：
- 每个角色识别到了哪些槽位
- 哪些图片**命名没被识别**（避免“放进去了却没生效”）

然后刷新浏览器即可。

## 五、不想按约定走？直接写路径

在 `data/characters.js` 里给角色加 `assets` 字段即可覆盖，优先级高于自动扫描：

```js
{
  id: "moyu", name: "摸鱼打工人", /* ... */
  assets: {
    idle:   "idle_01.png",                 // 也可以写数组：["idle_01.png","idle_02.png"]
    attack: "attack_02.png",
    skill:  "ult.gif",
    sfx: { attack: "sfx/punch.mp3" }
  }
}
```

路径规则：
- 普通写法（`idle.gif`）→ 相对 `assets/characters/<角色id>/`
- 以 `@` 开头（`@assets/common/shared.png`）→ 相对项目根目录
- 以 `/` 或 `http` 开头 → 原样使用（可指向外部地址）

## 六、素材规格建议

| 项目 | 建议 |
|---|---|
| 尺寸 | 128×128 或 256×256（会被缩放到角色大小，大一点更清晰） |
| 格式 | 有透明通道用 PNG/WEBP；动图用 GIF |
| 背景 | 透明 |
| 音效长度 | 0.1 ~ 0.6 秒，体积小、响度别太高 |
| 版权 | 请使用你有权使用的素材；本项目的默认几何图形均为原创绘制 |
